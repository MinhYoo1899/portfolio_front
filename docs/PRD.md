# PRD — 사내 게시판 (board-app)

## 목표

React 19 + Vite + TypeScript 기반의 **사내용 게시판 프론트엔드**를 백엔드 없이 동작 가능한 상태로 구축한다.
데이터 접근은 `PostRepository` 인터페이스로 추상화하여, 현재는 localStorage로 동작하고
향후 동일한 REST 계약으로 Flask/REST 백엔드를 끼워 넣을 수 있어야 한다.

## 기능 범위

### MVP (구현 완료)
- 게시글 CRUD (목록 · 상세 · 작성 · 수정 · 삭제)
- 고정 카테고리(공지/일반/질문/기타) 단일 선택 필터
- 통합 검색: 제목 + 본문 + 작성자 (대소문자 무시)
- 페이지네이션: 페이지 번호 방식, 20개/페이지
- 정렬: 최신순(기본) / 조회순
- 조회수: 상세 진입 시 세션당 1회 +1
- 마크다운 본문 렌더링
- Mock 로그인 + 역할(admin/user), 권한 기반 수정·삭제
- localStorage 영속화 (새로고침 후 유지)

### 추가 기능 (미구현, 확장 가능하게 설계됨)
- 댓글
- 마크다운 작성 중 실시간 미리보기
- 첨부파일
- 다크모드

### 나중 (별도 작업)
- 실제 Flask/REST 백엔드 연동
- 실제 로그인/권한 서버 검증
- 알림, 추천/좋아요, 인기순 정렬

## 비목표 (Non-Goals)
- SSR, i18n, 접근성 인증 수준 대응
- 정교한 조회수 중복 방지(세션 단위 단순 처리로 충분)

## 권한 모델
| 역할 | 권한 |
|------|------|
| 비로그인 | 목록·상세 읽기만 (수정/삭제 버튼 비표시) |
| user | 본인이 작성한 글만 수정/삭제 |
| admin | 모든 글 수정/삭제 |

> 권한은 UI 버튼 숨김 + **라우트 레벨 검증** 이중으로 적용된다.
> `/posts/:id/edit`는 글 로드 후 `canEditPost`가 거짓이면 상세로 리다이렉트한다(URL 직접 입력 방어).

## 수용 기준 (Acceptance Criteria)

| # | 기준 |
|---|------|
| AC1 | 목록에 제목·작성자·작성일·조회수·카테고리 표시 |
| AC2 | 작성 → 목록/상세 반영, 새로고침 후 유지, 목록 즉시 갱신 |
| AC3 | 상세에서 마크다운 렌더링 + 메타데이터 표시 |
| AC4 | 수정 시 `updatedAt` 갱신 및 유지 |
| AC5 | 삭제 확인 후 제거 및 유지 |
| AC6 | 권한별 수정/삭제 버튼 노출 (admin=전체, user=본인, 비로그인=숨김) |
| AC7 | 검색이 제목·본문·작성자 매칭 (대소문자 무시) |
| AC8 | 카테고리 단일 선택 필터 |
| AC9 | 20개/페이지 페이지 번호 이동 (시드 48개 → 3페이지) |
| AC10 | 최신순/조회순 정렬 전환 |
| AC11 | 상세 진입 시 조회수 +1 (세션당 1회, StrictMode 이중 마운트에도 1회) |
| AC12 | 데이터 접근이 `PostRepository` 경유 + localStorage 구현 주입 |
| AC13 | 목록·상세·작성·수정 페이지 로딩/에러 처리 + 라우터 errorElement |
| AC14 | mock 로그인 후 현재 사용자 localStorage 유지 |
| AC15 | 보호 라우트 비로그인 시 `/login?redirect=`로 이동 (same-origin 검증) |
| AC16 | 헤더에 사용자/역할 표시 + 로그아웃 |
| AC17 | `/posts/:id/edit` 라우트 레벨 권한 검증 |
| AC18 | 존재하지 않는 글 ID 진입 시 NotFound 처리 |
| AC-Q | `npm run build`, `npm run lint` 무오류 |

**검증 결과:** 전 항목 PASS (verifier 독립 검증, build/lint 0 에러).
